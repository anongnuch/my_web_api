# BRD-001 : ระบบบันทึกความเคลื่อนไหวสินค้าคงคลัง (Stock Movement)

| หัวข้อ | รายละเอียด |
|---|---|
| BRD ID | BRD-001 |
| Version | 1.0 |
| วันที่ | 2026-09-12 |
| ผู้จัดทำ | ฝ่าย Business Analyst |
| ผู้อนุมัติ | ผู้จัดการคลังสินค้า |
| ระบบที่เกี่ยวข้อง | stock_api (.NET 6 Web API) |

---

## 1. ความเป็นมาและปัญหาทางธุรกิจ

ปัจจุบันการรับสินค้าเข้าและเบิกสินค้าออกจากคลังถูกบันทึกด้วย Excel แยกไฟล์ตามเดือน ทำให้เกิดปัญหา

- ยอดคงเหลือในไฟล์ไม่ตรงกับของจริงบนชั้นวาง เพราะมีการแก้ไขย้อนหลังโดยไม่มีร่องรอย
- ไม่สามารถตรวจสอบได้ว่าใครเบิกสินค้ารายการใด เมื่อไร
- ไม่มีการแจ้งเตือนเมื่อสินค้าใกล้หมด ทำให้เกิดของขาดสต็อกเฉลี่ยเดือนละ 3-5 รายการ

## 2. วัตถุประสงค์ทางธุรกิจ (Business Objectives)

| ID | วัตถุประสงค์ | ตัวชี้วัด |
|---|---|---|
| BO-001 | ทำให้ยอดคงเหลือในระบบตรงกับของจริง | ผลต่างจากการนับสต็อกไม่เกิน 2% ต่อเดือน |
| BO-002 | ตรวจสอบย้อนหลังได้ว่าใครทำรายการอะไร | ทุกรายการมีผู้ทำรายการและเวลาครบ 100% |
| BO-003 | ลดปัญหาของขาดสต็อก | จำนวนรายการที่ขาดสต็อกลดลงเหลือไม่เกิน 1 รายการต่อเดือน |

## 3. ขอบเขต (Scope)

**อยู่ในขอบเขต (In Scope)**
- บันทึกรับสินค้าเข้าคลัง
- บันทึกเบิกสินค้าออกจากคลัง
- แสดงยอดคงเหลือและประวัติความเคลื่อนไหวรายสินค้า
- แจ้งเตือนสินค้าที่ยอดคงเหลือต่ำกว่าจุดสั่งซื้อ

**อยู่นอกขอบเขต (Out of Scope)**
- การสั่งซื้อสินค้าจากผู้ขาย (Purchase Order)
- การโอนย้ายสินค้าระหว่างคลัง
- การคิดต้นทุนสินค้าแบบ FIFO/Average
- ระบบ Barcode / RFID

## 4. ผู้เกี่ยวข้อง (Stakeholders & Actors)

| Actor | บทบาท | สิทธิ์ |
|---|---|---|
| เจ้าหน้าที่คลัง (Warehouse Staff) | บันทึกรับ-เบิกสินค้า ดูยอดคงเหลือ | สร้างรายการ, อ่านข้อมูล |
| หัวหน้าคลัง (Warehouse Supervisor) | ตรวจสอบและยกเลิกรายการที่ผิดพลาด | สิทธิ์ของเจ้าหน้าที่ + ยกเลิกรายการ |
| ระบบ (System) | ตรวจสอบกฎธุรกิจและสร้างการแจ้งเตือน | - |

## 5. ความต้องการทางธุรกิจ (Business Requirements)

| ID | ความต้องการ | สืบเนื่องจาก |
|---|---|---|
| BR-001 | ต้องบันทึกทุกความเคลื่อนไหวของสินค้าในระบบกลางเพียงแหล่งเดียว | BO-001 |
| BR-002 | ต้องเก็บร่องรอยผู้ทำรายการของทุกธุรกรรม | BO-002 |
| BR-003 | ต้องเตือนเจ้าหน้าที่ก่อนสินค้าหมด | BO-003 |

## 6. ความต้องการเชิงหน้าที่ (Functional Requirements)

| FR ID | ชื่อ | รายละเอียด | Priority |
|---|---|---|---|
| FR-001 | บันทึกรับสินค้าเข้าคลัง | เจ้าหน้าที่คลังระบุสินค้า จำนวน และเลขที่เอกสารอ้างอิง ระบบเพิ่มยอดคงเหลือและบันทึกประวัติ | High |
| FR-002 | บันทึกเบิกสินค้าออกจากคลัง | เจ้าหน้าที่คลังระบุสินค้า จำนวน และผู้ขอเบิก ระบบตรวจสอบยอดคงเหลือเพียงพอก่อนตัดสต็อก | High |
| FR-003 | แสดงยอดคงเหลือและประวัติความเคลื่อนไหว | แสดงยอดคงเหลือปัจจุบันรายสินค้า พร้อมประวัติรับ-เบิกย้อนหลัง กรองตามช่วงวันที่ได้ | Medium |
| FR-004 | แจ้งเตือนสินค้าใกล้หมด | เมื่อยอดคงเหลือหลังทำรายการต่ำกว่าหรือเท่ากับจุดสั่งซื้อ ระบบสร้างการแจ้งเตือนให้หัวหน้าคลัง | Medium |

## 7. กฎทางธุรกิจ (Business Rules)

| ID | กฎ |
|---|---|
| BL-001 | ยอดคงเหลือของสินค้าต้องไม่ติดลบในทุกกรณี |
| BL-002 | จำนวนที่รับหรือเบิกต้องเป็นจำนวนเต็มบวกมากกว่า 0 |
| BL-003 | ทุกรายการต้องบันทึกผู้ทำรายการและวันเวลาโดยระบบ ห้ามให้ผู้ใช้แก้ไข |
| BL-004 | การยกเลิกรายการทำได้เฉพาะหัวหน้าคลัง และภายใน 24 ชั่วโมงหลังสร้างรายการ |
| BL-005 | จุดสั่งซื้อ (Reorder Point) กำหนดได้รายสินค้า ค่าเริ่มต้นเท่ากับ 10 หน่วย |
| BL-006 | การบันทึกรายการต้องอ้างอิงสินค้าที่มีสถานะ Active เท่านั้น |

## 8. ความต้องการที่ไม่ใช่เชิงหน้าที่ (Non-Functional Requirements)

| ID | ความต้องการ |
|---|---|
| NFR-001 | API ต้องตอบสนองภายใน 2 วินาทีที่ปริมาณผู้ใช้พร้อมกัน 20 คน |
| NFR-002 | ต้องมี Audit Log ที่ไม่สามารถลบได้ เก็บย้อนหลังอย่างน้อย 1 ปี |
| NFR-003 | ต้องยืนยันตัวตนด้วย JWT ก่อนเรียกใช้ทุก endpoint |
| NFR-004 | การตัดสต็อกต้องทำภายใน Transaction เดียวเพื่อกัน Race Condition |

## 9. สมมติฐานและข้อจำกัด

- ข้อมูลสินค้า (Product) และผู้ใช้ (User) มีอยู่ในระบบเดิมแล้ว ไม่ต้องสร้างใหม่
- ใช้ฐานข้อมูลเดิมของ stock_api ไม่มีการย้ายฐานข้อมูล
- การแจ้งเตือนในเฟสนี้แสดงในระบบเท่านั้น ยังไม่ส่งอีเมลหรือ LINE

## 10. เกณฑ์การยอมรับระดับโครงการ (Success Criteria)

- ผ่าน Test Case ทั้งหมดของ FR-001 ถึง FR-004
- ยอดคงเหลือที่คำนวณจากประวัติความเคลื่อนไหวตรงกับยอดคงเหลือที่เก็บในตารางสินค้า
- หัวหน้าคลังเห็นรายการแจ้งเตือนสินค้าใกล้หมดได้ภายในวันเดียวกับที่เกิดเหตุ
